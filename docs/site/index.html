    DesktopSubsystem

    For Android™

    DSA runs the whole of Android in a dedicated virtual machine and shows each app as a real window on your PC. The taskbar, notifications, keyboard input and file drag and drop work the way they do for any other desktop app.

    How it works

    Android stays whole. The boundary is the HAL.

    The kernel, ART and the framework stay inside a dedicated VM. Only the display and the devices move to your PC.

    01 / 08Windows

    One app, one window

    Every task gets its own window with its own icon and name. Snap, Alt+Tab and the taskbar just work.

    • Integrated title bar
    • Snap layouts
    • Start menu and taskbar
    02 / 08Graphics

    Your GPU does the drawing

    Your PC's GPU runs each app's OpenGL ES and Vulkan, and the renderer lives in a process of its own.

    • ANGLE
    • Vulkan remoting
    • GPU reset recovery
    03 / 08Memory

    Unused memory goes back

    While Android rests, its free memory goes straight back to Windows. There is no fixed cap.

    • Free page reporting
    • Doze when idle
    • Opt-in freeze
    04 / 08ARM apps

    ARM apps too

    The x86 build runs when there is one. Only ARM-only apps go through translation, with an open source translator by default.

    • x86 first
    • Default translator
    • Swap the translator
    05 / 08Devices

    Devices live on the host

    Camera, audio and codecs run on the PC as HAL services. Android never forwards a system call.

    • RPC Binder
    • Host codecs
    • Camera and audio
    06 / 08Files

    Drag, drop and paste

    Drop files on a window and share the clipboard. Try dragging the ball in the middle.

    • File drag and drop
    • Shared clipboard
    • APK Installer
    07 / 08Idle

    Opens without the wait

    Closing the last window puts Android into Doze instead of shutting it down, so the next app opens without a boot.

    • Doze by default
    • Notifications
    • Desktop widgets
    08 / 08Hosts

    One Android, three hosts

    Windows comes first. The protocol and the guest are the same on Linux and macOS.

    • Windows 11
    • Linux (in progress)
    • macOS (in progress)
    Memory

    No fixed cap. Only what it needs.

    The VM, the window manager, the renderer and each app window take only what they need.

    Desktop integration

    Part of the desktop

    • Host keyboard and IME

      Your Windows input method composes text inline, Korean included. No Android keyboard appears.

      TSF→InputConnection

    • Notifications

      Android notifications appear as Windows notifications, and selecting one opens the app's window.

      NotificationListener→toast

    • APK Installer

      Double-click an APK to see its name, publisher, version and permissions before it installs.

      dsa install notes-2.8.1.apk

    • Desktop widgets

      Place Android widgets on the Windows desktop. Resize one and it redraws at that size.

      dsa widgets

    • Network

      Your PC answers Android's name lookups, so the hosts file, a VPN and DNS filters apply as they do to Windows apps.

      dsa network

    • Google Play installer

      DSA ships no Google software. If you want Google Play, DSA downloads the public package after showing you its source and terms.

      dsa gapps install
    Command line

    Whatever Settings does, a command does too.

    • dsa statusAndroid session state
    • dsa startStart Android
    • dsa stopStop Android
    • dsa updateInstall the newest DSA now
    • dsa launchOpen an app in a window
    • dsa tasksOpen tasks and their windows
    • dsa appsInstalled apps: list, details, uninstall
    • dsa installInstall an APK
    • dsa apk-infoSee what an APK is before installing
    • dsa widgetsPlace and remove desktop widgets
    • dsa memoryMemory Android takes
    • dsa networkNetwork mode, addresses and DNS
    • dsa settingsShow or change a setting
    • dsa androidShow or switch the Android version
    • dsa gappsInstall Google Play, if you want it
    • dsa logs collectSave a diagnostics archive
