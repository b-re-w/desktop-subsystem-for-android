# Приложения и окна

[English](../apps.md) · [한국어](../ko/apps.md) · [日本語](../ja/apps.md) · [简体中文](../zh-CN/apps.md) · [繁體中文](../zh-TW/apps.md) · [Español](../es/apps.md) · [Français](../fr/apps.md) · [Deutsch](../de/apps.md) · [Português (Brasil)](../pt-BR/apps.md) · **Русский** · [Italiano](../it/apps.md) · [Tiếng Việt](../vi/apps.md) · [Bahasa Indonesia](../id/apps.md) · [Türkçe](../tr/apps.md)

Каждая задача приложения Android открывается в собственном окне рабочего стола со своей кнопкой
на панели задач. Вокруг экрана телефона нет рамки эмулятора. На этой странице описан Desktop
Subsystem for Android™ (DSA) в Windows.

## Открытие приложения

- **Меню «Пуск».** У каждого установленного приложения есть пункт в меню «Пуск» с его
  собственным именем и значком, поэтому его находит поиск Windows. Если Android не запущен, при
  открытии сначала запускается Android.
- **DSA Settings.** На странице **Apps** (приложения) выберите **Open** рядом с приложением.
- **Командная строка.** `dsa apps list` выводит установленные приложения с их пакетами.
  `dsa launch <package>` открывает одно из них, например `dsa launch com.android.settings`.

Если у пункта меню «Пуск» другой программы уже есть такое же имя, DSA добавляет к имени пакет,
например `Clock (com.example.clock)`. DSA изменяет или удаляет только те пункты, которые создал
сам.

## Ярлыки на рабочем столе и списки переходов

Значки приложений работают так же, как у приложений Windows, а не как на главном экране
Android.

- **Ярлык на рабочем столе.** На странице **Apps** в DSA Settings выберите **Create desktop
  shortcut** рядом с приложением. Можно также щёлкнуть правой кнопкой мыши кнопку приложения на
  панели задач и выбрать **Create desktop shortcut**. Из командной строки:
  `dsa apps desktop-shortcut <package>`. Ярлык открывает приложение так же, как его пункт в
  меню «Пуск».
- **Ярлыки приложения.** Ярлыки, которые предлагает приложение Android, например новый чат в
  мессенджере, появляются, когда вы щёлкаете правой кнопкой мыши кнопку приложения на панели
  задач или его пункт в меню «Пуск». Выбор ярлыка открывает соответствующий экран приложения в
  окне, а если Android не запущен, сначала запускает его. Когда приложение меняет свои ярлыки,
  список обновляется. Из командной строки: `dsa apps shortcut <package> <id>`, а
  `dsa apps info <package> --json` выводит идентификаторы.
- **Ярлыки, которые запрашивает приложение.** Когда приложение просит добавить один из своих
  ярлыков на рабочий стол, DSA сначала спрашивает вас и добавляет ярлык, только если вы
  согласны.

Когда приложение меняет имя, например после обновления, его пункт в меню «Пуск», ярлыки на
рабочем столе и закрепление на панели задач получают новое имя и продолжают работать. Удалённый
вами ярлык на рабочем столе не создаётся снова. При удалении приложения удаляются и его ярлыки
на рабочем столе.

## Работа с окнами приложений

- У каждой задачи своё окно, своя кнопка на панели задач и свой пункт в Alt+Tab, с именем и
  значком приложения. Диспетчер задач показывает каждое приложение под его собственным именем.
- Строка заголовка является частью приложения: цвета приложения доходят до верхнего края окна,
  а кнопки заголовка Windows 11 располагаются поверх них. Значок и имя приложения находятся
  слева. Когда приложение может вернуться назад, значок превращается в стрелку «Назад».
  Выберите её, чтобы вернуться.
- Работают макеты прикрепления (наведите указатель на кнопку развёртывания), перетаскивание за
  строку заголовка, развёртывание двойным щелчком по ней и изменение размера на лету. Изменение
  размера не перезапускает приложение. Развёрнутое окно заполняет рабочую область монитора и
  оставляет панель задач видимой.
- Панели навигации Android нет. Нижняя панель приложения находится у нижнего края окна, без
  пустой полосы под ней.
- Работают мышь (с наведением), сенсорный ввод, перо (нажим, ластик и боковая кнопка) и
  клавиатура. Текст поступает из вашего метода ввода Windows, включая корейский и другие языки.
  Составляемый текст отображается прямо в редакторе Android, а окно кандидатов находится рядом
  с курсором. Приложения клавиатуры Android нет.
- Перетаскивайте файлы из проводника на окно приложения или из приложения в проводник.
- Программы чтения с экрана, такие как Экранный диктор (Narrator) и NVDA, читают приложение
  через UI Automation.
- Закрытие окна просит Android завершить эту задачу.

## Меню окна

Щёлкните правой кнопкой мыши строку заголовка, выберите значок приложения или нажмите
Alt+Пробел. После обычных пунктов Windows в меню есть:

- **Full screen** (полный экран): заполняет весь экран, как F11. Чтобы выйти, выберите этот
  пункт снова или нажмите F11.
- **New window** (новое окно): открывает ещё одно окно приложения, если приложение
  поддерживает несколько окон.
- **Screenshot** (снимок экрана): копирует экран приложения без строки заголовка в буфер
  обмена и сохраняет его в папке «Снимки экрана» в ваших «Изображениях».
- **Aspect ratio** (соотношение сторон): открывает параметр Android для соотношения сторон
  приложения, для приложений, которые в большом окне выглядят растянутыми.
- **Open by default** (открывать по умолчанию): определяет, открываются ли поддерживаемые
  приложением ссылки в приложении или в вашем браузере.
- **App info** (о приложении): открывает запись приложения на странице **Apps** в DSA
  Settings.

## Полноэкранный режим

Когда приложение запрашивает полноэкранный режим, его окно показывает его одним из двух
способов:

- **На весь экран**: окно заполняет монитор, а строка заголовка скрывается. Чтобы показать её,
  коснитесь указателем верхнего края экрана. В ней есть кнопки «Свернуть» и «Закрыть», а
  средняя кнопка выходит из полноэкранного режима.
- **Внутри окна**: окно сохраняет свой размер и строку заголовка, а приложение заполняет его.

Приложения запрашивают это двумя способами, и у каждого своё значение по умолчанию:

| Вид запроса | Пример | По умолчанию |
|---|---|---|
| Явный запрос полноэкранного режима | Кнопка полного экрана в видеоплеере | На весь экран |
| Только скрытие панелей | Лента коротких видео | Внутри окна |

Значения по умолчанию меняются параметрами **App full screen** и **Apps that hide their bars**
на странице **Display & GPU** (экран и GPU) в DSA Settings, а для отдельного приложения
параметрами **Full screen request** и **When only the bars hide** на странице **Apps**. Собственный выбор
приложения имеет приоритет. F11 и пункт **Full screen** в меню окна в любой момент переключают
полноэкранный режим на весь экран, независимо от параметра.

Из командной строки:

```
dsa settings set app-fullscreen screen|window           # по умолчанию для явных запросов
dsa settings set app-immersive screen|window            # по умолчанию для скрытых панелей
dsa app-window <package> --fullscreen screen|window|default
dsa app-window <package> --immersive screen|window|default
```

## Размер окна приложения

На странице **Apps** в DSA Settings:

- Выключите **Resizable** (изменяемый размер), чтобы окна приложения сохраняли размер, с
  которым они открываются.
- Выберите размер, с которым открываются окна приложения: размер, который выбирает Android, или
  размер телефона или планшета в книжной или альбомной ориентации.

Изменение применяется к следующему окну, которое откроет приложение. Из командной строки:

```
dsa app-window <package> --fixed-size on        # нельзя изменить размер или развернуть
dsa app-window <package> --start-size 1280x800  # открывается с этим размером; auto оставляет выбор Android
dsa app-window <package> --dpi-scaling system   # как масштабируется на другом мониторе; см. ниже
dsa app-window <package> reset                  # вернуть значения по умолчанию
```

## Запуск приложения под строкой заголовка

Приложение рисует до самого верха своего окна, под строкой заголовка. Из-за этого некоторые
приложения сжимают свою верхнюю панель или прячут её часть под строкой заголовка. Для такого
приложения включите **Start below the title bar** (начинать под строкой заголовка) на странице **Apps** в DSA Settings.
Тогда содержимое приложения начинается под строкой заголовка, а строка заголовка принимает
цвет, который приложение показывает в этом месте. По умолчанию параметр выключен и
применяется при следующем открытии окна приложения. В командной строке:

```
dsa app-window <package> --below-title-bar on   # off возвращает значение по умолчанию
```

## Перенос приложения на монитор с другим масштабом

Android запускается с масштабом основного монитора, поэтому приложения открываются там в
правильном размере. Когда вы переносите окно
на монитор с другим масштабом, приложение сохраняет свой размер на экране, а при **Automatic** и **System** оно никогда не перезапускается. Каждое приложение
делает это одним из следующих способов, который выбирается параметром **Scaling** на странице **Apps** или командой `dsa app-window <package> --dpi-scaling`:

- **Automatic** (`auto`, по умолчанию): **System** для приложений из встроенного в DSA списка
  приложений, которые ломаются при смене масштаба во время работы. Для любого другого
  приложения: **App**, если оно заявляет, что само обрабатывает смену масштаба, и **System**,
  если нет. В списке есть YouTube: он сохраняет разметку для масштаба, с которым запустился,
  поэтому после переноса его нижние вкладки и мини-плеер оставались бы сломанными до
  перезапуска. Для такого приложения Settings показывает значение по умолчанию как
  **Automatic (system, recommended for this app)**. Ваш собственный выбор для приложения
  имеет приоритет.
- **App** (`app`): приложение перерисовывается в масштабе нового монитора, как только окно
  попадает туда, и текст остаётся чётким. Если приложение не заявляет, что само обрабатывает
  смену масштаба, Android пересоздаёт его экран и восстанавливает состояние (положение
  прокрутки, введённый текст), поэтому при переносе оно может ненадолго перерисоваться, как
  программа Windows с масштабированием «Приложение».
- **System** (`system`): приложение сохраняет свой масштаб, а DSA масштабирует его окно под
  новый монитор. При увеличении текст может выглядеть немного размытым.
- **System (forced)** (`system-forced`): приложение получает новый масштаб без перезапуска,
  даже если не заявляет, что умеет его обрабатывать. Пока недоступно: для этого нужно изменение
  в Android, которого нет в этой версии, поэтому до тех пор этот вариант работает как
  **System**.

Текст в приложениях следует размеру текста Windows («Параметры > Специальные возможности >
Размер текста»).

## Уведомления

Уведомления Android отображаются как уведомления Windows, с именем и значком приложения.

- Выберите уведомление, чтобы открыть приложение.
- Закройте уведомление, и оно закроется и в Android, если только приложение не удерживает его.
- Уведомления продолжают приходить, пока Android находится в Doze. См. [Память](memory.md).

## Приложения, работающие в фоне

Приложение, которое продолжает работать после закрытия окна, например музыкальный плеер,
отображается значком в области уведомлений. Его всплывающая подсказка является уведомлением
приложения.

- Выберите значок, чтобы открыть приложение.
- Щёлкните его правой кнопкой мыши, чтобы увидеть **Open**, собственные действия уведомления и
  **Stop**.
- **Stop** сначала спрашивает подтверждение. Отметьте **Do not ask again**, чтобы больше не
  видеть вопроса. Чтобы вопрос снова появлялся, включите **Ask before stopping an app from the
  notification area** на странице **Running in the background** (работа в фоне) в DSA
  Settings.
- Приложение, воспроизводящее медиа, также работает с мультимедийными клавишами и элементами
  управления мультимедиа Windows.

Страница **Running in the background** в DSA Settings перечисляет эти приложения с кнопками
**Open** и **Stop** для каждого. Из командной строки: `dsa background`,
`dsa background open <package>` и `dsa background stop <package>`.

## Виджеты на рабочем столе

Виджет Android может находиться на рабочем столе в собственном окне. Он остаётся под другими
окнами, не исчезает, когда вы показываете рабочий стол, и не отображается на панели задач и в
Alt+Tab.

1. Откройте страницу **Widgets** (виджеты) в DSA Settings.
2. В разделе **Widgets your apps offer** выберите **Add to desktop** рядом с виджетом. Если
   приложение просит настроить виджет, его настройка открывается в окне.
3. Чтобы переместить виджет, нажмите в любом его месте и полсекунды не двигайте указатель.
   Виджет приподнимается, появляются рамка и маркеры на каждой стороне, по которой можно менять
   его размер. Перетащите виджет, чтобы переместить его, или перетащите маркер, чтобы изменить
   размер. Быстрое перетаскивание остаётся за самим виджетом, поэтому его списки по-прежнему
   прокручиваются. Можно также перетащить край виджета, чтобы изменить размер без
   предварительного подъёма. Так работают только те края, по которым можно менять размер. DSA
   запоминает, где вы разместили виджет и какого он размера.
4. Щёлкните виджет правой кнопкой мыши или отпустите его после долгого нажатия, чтобы увидеть
   **Widget settings** (если виджет можно настроить заново), **Resize** для выбора одного из
   допустимых размеров и **Remove**. Это меню также открывают клавиша меню и Shift+F10. В этом
   меню работают клавиши со стрелками, Enter и Esc, а буква выбирает пункт: R для **Resize** и M
   для **Remove**.

Из командной строки: `dsa widgets list`, `dsa widgets add <provider>` и
`dsa widgets remove <id>`.

## Ссылки и буфер обмена

- Веб-ссылка, которую вы нажимаете в приложении Android, открывается в браузере по умолчанию.
  Ссылка, которую установленное приложение подтвердило как свою, открывается в этом приложении.
- Чтобы вместо этого открывать все веб-ссылки в приложениях Android, включите **Open web links
  in Android apps** на странице **Advanced** (дополнительно) в DSA Settings
  (`dsa settings set links-in-android on`).
- Копируемый текст передаётся между Windows и Android в обе стороны. Чтобы отключить это,
  выключите **Share the clipboard with Android** на странице **Advanced**
  (`dsa settings set clipboard off`).

## Google Play и защищённое видео

DSA не поставляет программы Google. Если они вам нужны, DSA загружает их для вас из источника,
предварительно показав источник и условия. Оба дополнения начинают действовать со следующего
запуска Android, и оба можно снова удалить.

- **Google Play.** На странице **Advanced** в DSA Settings выберите **Install** в разделе
  **Google Play** или выполните `dsa gapps install`. DSA загружает общедоступный пакет
  LiteGapps Core (сервисы Google Play, Play Маркет и синхронизация аккаунта) для вашей версии
  Android. Этот Android не сертифицирован Google, поэтому Google может отказывать во входе,
  пока вы не зарегистрируете устройство: **Register this device with Google** показывает
  Android ID и открывает страницу регистрации. `dsa gapps status` показывает состояние, а
  `dsa gapps remove` удаляет приложения Google, даже когда Android остановлен.
- **Widevine.** Стриминговым приложениям для воспроизведения защищённого видео нужен модуль
  Widevine от Google. На странице **Advanced** выберите **Get** в разделе **Protected content**
  или выполните `dsa drm widevine install`. DSA загружает образ эмулятора Android от Google для
  вашей версии Android (около 2 ГБ), сохраняет только модуль Widevine без изменений и удаляет
  остальное. Widevine здесь имеет уровень безопасности L3, поэтому стриминговые сервисы
  передают видео не выше стандартной чёткости. Для высокой чёткости пользуйтесь браузером или
  приложением Windows. `dsa drm widevine remove` удаляет модуль.

## Приложения только для ARM

На ПК с x64 приложение, код которого есть только для процессоров ARM, работает через
транслятор ARM. Android на ПК с x64 поставляется с транслятором с открытым исходным кодом
Digitalis и использует его с первого запуска. Вместо него можно использовать другой:

- **Транслятор ARM от Google.** На странице **Advanced** выберите **Get** рядом с **Google's
  ARM translator** или выполните `dsa arm-translation fetch google`. DSA сначала показывает,
  откуда он берётся, и условия Google
  ([Android SDK License](https://developer.android.com/studio/terms)) и ничего не загружает,
  пока вы их не примете. Затем ваш ПК загружает образ эмулятора Android, который Google
  предлагает для вашей версии Android (около 2 ГБ), сохраняет только транслятор и удаляет
  остальное. DSA не поставляет и не распространяет транслятор Google.
- **Пакет, который вы собрали сами или получили из другого источника**, например созданный на
  основе транслятора с открытым исходным кодом Digitalis:
  `dsa arm-translation install <folder>`.

Затем перезапустите Android: остановите его на странице **General** (общие) в DSA Settings, а
потом откройте приложение.

Чтобы вернуться к транслятору, который поставляется с Android, выберите **Use** рядом с **Use
the default translator** на странице **Advanced** или выполните
`dsa arm-translation use-default`. Это удаляет установленный вами пакет начиная со следующего
запуска Android.

`dsa arm-translation status` сообщает, какой транслятор использует Android. Переключатель
**Run apps built only for ARM** на странице **Advanced** включает или выключает трансляцию,
ничего не удаляя. Для приложения, у которого есть код и для ARM, и для x64, параметр **Run as
ARM** на странице **Apps** (`dsa apps run-as-arm <package> on`) запускает вместо этого его код
ARM. Работать могут только 64-битные приложения ARM (`arm64-v8a`). На ПК с ARM64 Android сам
запускает приложения ARM, и транслятор не нужен.

## Права root

Некоторым приложениям, например средствам резервного копирования, нужны права root. DSA
предоставляет их так же, как `sudo` на ПК с Linux: только с одобрения администратора ПК, по
одному запросу за раз. По умолчанию это выключено, а приложения без разрешения вообще не видят
`su`.

1. Администратор включает **Let Android apps ask for root** в разделе **Root access** на
   странице **Advanced** в DSA Settings (`dsa settings set root-elevation on`). Это начинает
   действовать со следующего запуска Android.
2. На странице **Apps** задайте для приложения параметр **Root access**:
   - **Root: not allowed** (по умолчанию): у приложения нет `su`.
   - **Root: ask each time**: каждый раз, когда приложение использует `su`, Windows показывает
     окно администратора (UAC) с именем и значком самого приложения. Обычный пользователь
     вводит пароль администратора. Одобрение действует 15 минут для этого приложения.
   - **Root: remember (no asking)**: приложение использует `su` без запроса. Для выбора этого
     варианта нужно одобрение администратора.

   Из командной строки: `dsa apps root <package> off|ask|remember`.

При включённом режиме разработчика `su` может использовать и `adb shell`. У него есть своя
строка на странице **Apps**, **adb shell**, и по умолчанию он спрашивает каждый раз
(`dsa apps root adb ask`). Его запрос называется **adb shell** и показывает команду.

Когда запрос исходит от части самого Android, окно запроса называет её: **Android system**,
**Android phone services**, **Android Bluetooth**, **Android NFC** или **Android system
service**. Приложения с общим идентификатором пользователя одобряются одной группой, и окно
запроса перечисляет их все.

Каждый запрос сохраняется в журнале службы с приложением, временем, командой и тем, был ли он
одобрен. Выключение функции сразу скрывает `su` от всех приложений, без перезапуска.
