# 앱과 창

[English](../apps.md) · **한국어** · [日本語](../ja/apps.md) · [简体中文](../zh-CN/apps.md) · [繁體中文](../zh-TW/apps.md) · [Español](../es/apps.md) · [Français](../fr/apps.md) · [Deutsch](../de/apps.md) · [Português (Brasil)](../pt-BR/apps.md) · [Русский](../ru/apps.md) · [Italiano](../it/apps.md) · [Tiếng Việt](../vi/apps.md) · [Bahasa Indonesia](../id/apps.md) · [Türkçe](../tr/apps.md)

Android 앱의 작업은 하나하나 독립된 데스크톱 창으로 열리고, 작업 표시줄 단추도 따로 가집니다.
휴대폰 화면을 둘러싼 에뮬레이터 틀은 없습니다. 이 페이지는 Windows용 Desktop Subsystem for
Android™(DSA)를 설명합니다.

## 앱 열기

- **시작 메뉴**: 설치된 앱마다 자기 이름과 아이콘으로 시작 메뉴에 항목이 생기므로 Windows
  검색으로도 찾을 수 있습니다. Android가 실행 중이 아니면 먼저 Android를 시작합니다.
- **DSA 설정**: **앱** 페이지에서 앱 옆의 **열기**를 누릅니다.
- **명령줄**: `dsa apps list`는 설치된 앱과 패키지 이름을 보여 줍니다. `dsa launch <package>`는
  앱을 엽니다. 예: `dsa launch com.android.settings`

다른 프로그램의 시작 메뉴 항목이 이미 같은 이름을 쓰고 있으면, DSA는 이름 뒤에 패키지 이름을
붙입니다. 예: `Clock (com.example.clock)`. DSA는 자기가 만든 항목만 바꾸거나 지웁니다.

## 바탕 화면 바로 가기와 점프 목록

앱 아이콘은 Android 홈 화면이 아니라 Windows 앱과 같은 방식으로 다룹니다.

- **바탕 화면 바로 가기**: DSA 설정의 **앱** 페이지에서 앱 옆의 **바탕 화면 바로 가기 만들기**를
  누릅니다. 앱의 작업 표시줄 단추를 마우스 오른쪽 단추로 눌러 **바탕 화면 바로 가기 만들기**를
  골라도 됩니다. 명령줄에서는 `dsa apps desktop-shortcut <package>`를 씁니다. 바로 가기는 시작
  메뉴 항목과 똑같이 앱을 엽니다.
- **앱 바로 가기**: 메신저의 새 채팅처럼 Android 앱이 제공하는 바로 가기는 앱의 작업 표시줄
  단추나 시작 메뉴 항목을 마우스 오른쪽 단추로 누르면 나옵니다. 하나를 고르면 앱의 그 화면이
  창으로 열리고, Android가 실행 중이 아니면 먼저 시작합니다. 앱이 바로 가기를 바꾸면 목록도 따라
  바뀝니다. 명령줄에서는 `dsa apps shortcut <package> <id>`를 쓰며, ID는
  `dsa apps info <package> --json`으로 확인합니다.
- **앱이 요청한 바로 가기**: 앱이 자기 바로 가기를 바탕 화면에 추가하려고 하면 DSA가 먼저 묻고,
  동의할 때만 추가합니다.

업데이트 뒤처럼 앱의 이름이 바뀌면, 시작 메뉴 항목, 바탕 화면 바로 가기, 작업 표시줄 고정이 새
이름을 따르고 계속 동작합니다. 지운 바탕 화면 바로 가기는 다시 만들어지지 않습니다. 앱을
제거하면 그 앱의 바탕 화면 바로 가기도 함께 지워집니다.

## 앱 창 다루기

- 작업마다 창, 작업 표시줄 단추, Alt+Tab 항목이 따로 있고, 앱의 이름과 아이콘이 표시됩니다.
  작업 관리자에도 앱마다 자기 이름으로 나타납니다.
- 제목 표시줄은 앱의 일부입니다. 앱의 색이 창 맨 위까지 닿고, 그 위에 Windows 11 캡션 단추가
  놓입니다. 왼쪽에는 앱의 아이콘과 이름이 있습니다. 앱이 뒤로 갈 수 있으면 아이콘이 뒤로
  화살표로 바뀌며, 누르면 뒤로 갑니다.
- 스냅 레이아웃(최대화 단추에 마우스를 올립니다), 제목 표시줄 끌기, 두 번 클릭해 최대화, 실시간
  크기 조정을 쓸 수 있습니다. 창 크기를 바꿔도 앱이 다시 시작되지 않습니다. 최대화한 창은
  모니터의 작업 영역을 채우고 작업 표시줄은 보이게 둡니다.
- Android 탐색 모음은 없습니다. 앱의 아래쪽 막대는 창의 아래쪽 끝에 붙고, 그 아래에 빈 띠가
  없습니다.
- 마우스(호버 포함), 터치, 펜(필압, 지우개, 측면 단추), 키보드를 모두 쓸 수 있습니다. 글자는
  한국어를 비롯한 Windows 입력기로 입력합니다. 조합 중인 글자는 Android 편집기 안에 바로 보이고,
  후보 창은 커서 옆에 뜹니다. Android 키보드 앱은 없습니다.
- 파일 탐색기에서 앱 창으로 파일을 끌어 놓거나, 앱에서 파일 탐색기로 파일을 끌어 낼 수
  있습니다.
- 내레이터, NVDA 같은 화면 읽기 프로그램이 UI Automation으로 앱을 읽습니다.
- 창을 닫으면 Android에 그 작업을 끝내도록 요청합니다.

## 창 메뉴

제목 표시줄을 마우스 오른쪽 단추로 누르거나, 앱 아이콘을 누르거나, Alt+Space를 누릅니다.
일반적인 Windows 항목 다음에 이런 항목이 있습니다.

- **전체 화면**: F11처럼 화면 전체를 채웁니다. 다시 고르거나 F11을 누르면 빠져나옵니다.
- **새 창**: 창 여러 개를 지원하는 앱에서 앱의 창을 하나 더 엽니다.
- **스크린샷**: 제목 표시줄을 뺀 앱 화면을 클립보드에 복사하고, 사진 폴더 안의 스크린샷 폴더에
  저장합니다.
- **화면 비율**: 큰 창에서 늘어나 보이는 앱을 위해, 앱의 화면 비율을 정하는 Android 설정을
  엽니다.
- **링크 열기 설정**: 앱이 지원하는 링크를 앱에서 열지, 브라우저에서 열지 고릅니다.
- **앱 정보**: DSA 설정 **앱** 페이지에서 그 앱의 항목을 엽니다.

## 전체 화면

앱이 전체 화면을 요청하면, 창은 두 방식 중 하나로 보여 줍니다.

- **화면 전체로**: 창이 모니터를 채우고 제목 표시줄이 숨습니다. 포인터를 화면 위쪽 끝에 대면
  최소화, 닫기와 함께 제목 표시줄이 나타납니다. 가운데 단추를 누르면 전체 화면을 끝냅니다.
- **창 안에서**: 창은 크기와 제목 표시줄을 그대로 두고, 앱이 창을 채웁니다.

앱이 요청하는 방식은 두 가지이고, 방식마다 기본값이 따로 있습니다.

| 요청 종류 | 예 | 기본값 |
|---|---|---|
| 분명한 전체 화면 요청 | 동영상 플레이어의 전체 화면 단추 | 화면 전체로 |
| 막대만 숨기기 | 짧은 동영상 피드 | 창 안에서 |

기본값은 DSA 설정 **디스플레이 및 GPU** 페이지의 **앱의 전체 화면**과 **막대를 숨기는 앱**에서
바꿉니다. 앱 하나만 바꾸려면 **앱** 페이지의 **전체 화면**과 **막대 숨김**을 씁니다. 앱마다 고른
값이 먼저입니다. F11과 창 메뉴의 **전체 화면**은 설정과 관계없이 언제든 화면 전체로 보는 전체
화면을 켜고 끕니다.

명령줄에서는 다음과 같이 합니다.

```
dsa settings set app-fullscreen screen|window           # 분명한 요청의 기본값
dsa settings set app-immersive screen|window            # 막대를 숨길 때의 기본값
dsa app-window <package> --fullscreen screen|window|default
dsa app-window <package> --immersive screen|window|default
```

## 앱 창 크기 정하기

DSA 설정의 **앱** 페이지에서 정합니다.

- **크기 조절**을 끄면 앱 창이 열린 크기 그대로 유지됩니다.
- 앱 창이 처음 열리는 크기를 고릅니다. Android가 정한 크기, 또는 휴대폰이나 태블릿의 세로, 가로
  크기 중에서 고를 수 있습니다.

바꾼 설정은 앱이 다음에 여는 창부터 적용됩니다. 명령줄에서는 다음과 같이 합니다.

```
dsa app-window <package> --fixed-size on        # 크기 조정과 최대화를 막습니다
dsa app-window <package> --start-size 1280x800  # 이 크기로 엽니다. auto는 Android가 정합니다
dsa app-window <package> --dpi-scaling system   # 다른 모니터에서 맞추는 방식입니다. 아래를 참고하십시오
dsa app-window <package> reset                  # 기본값으로 되돌립니다
```

## 배율이 다른 모니터로 앱 옮기기

앱은 창이 열리는 모니터의 배율로 첫 프레임부터 열리므로, 열린 직후에 다시 만들어지지 않습니다.
창을 배율이 다른 모니터로 옮기면 앱은 화면에서 같은 크기를 유지합니다. 앱마다 다음 방식 중
하나로 맞추며, **앱** 페이지의 **다른 모니터에서의 크기 조정**이나
`dsa app-window <package> --dpi-scaling`으로 고릅니다.

- **자동**(`auto`, 기본값): 실행 중에 배율이 바뀌면 깨지는 앱을 모은 DSA의 기본 목록에 있는 앱은
  **시스템** 방식, 그 밖의 앱은 **앱** 방식입니다. 목록에는 YouTube가 있습니다. YouTube는 시작할
  때의 배율에 맞춘 레이아웃을 지니고 있어, 옮긴 뒤에는 다시 시작할 때까지 아래 탭과 미니플레이어가
  깨진 채 남습니다. 설정은 이런 앱의 기본값을 **크기 조정: 시스템 (이 앱에 맞춤)** 항목으로
  보여 줍니다. 사용자가 그 앱에 고른 방식이 먼저입니다.
- **앱**(`app`): 창을 끄는 동안에는 DSA가 창을 새 모니터에 맞게 늘이거나 줄입니다. 손을 떼면 앱이
  새 모니터의 배율로 다시 그리고, 글자가 선명하게 유지됩니다. Android가 화면을 한 번 다시 만들고
  상태(스크롤 위치, 입력한 글자)를 되살리므로, 옮길 때마다 잠깐 다시 그려집니다. Windows
  프로그램의 "응용 프로그램" 크기 조정과 같습니다. 배율 변화를 직접 처리한다고 밝힌 앱도
  마찬가지입니다. 그런 앱 가운데 일부는 화면의 일부만 새 배율로 다시 그리기 때문입니다.
- **시스템**(`system`): 앱은 배율을 그대로 두고, DSA가 창을 새 모니터에 맞게 늘이거나 줄입니다.
  앱을 다시 만들지 않습니다. 늘이면 글자가 조금 흐려질 수 있습니다.
- **시스템(강제)**(`system-forced`): 배율 변화를 처리한다고 밝히지 않은 앱에도 재시작 없이 새
  배율을 넘깁니다. 아직 쓸 수 없습니다. 이 버전에 없는 Android 변경이 필요하므로, 그때까지는
  **시스템**처럼 동작합니다.

앱의 글자는 Windows 텍스트 크기(설정 > 접근성 > 텍스트 크기)를 따릅니다.

## 알림

Android 알림은 앱 이름과 아이콘이 붙은 Windows 알림으로 나타납니다.

- 알림을 누르면 앱이 열립니다.
- 알림을 닫으면 Android에서도 닫힙니다. 앱이 계속 표시하도록 정한 알림은 예외입니다.
- Android가 Doze 상태여도 알림은 계속 옵니다. [메모리](memory.md)를 참고하십시오.

## 백그라운드에서 실행 중인 앱

음악 재생 앱처럼 창을 닫은 뒤에도 계속 실행되는 앱은 알림 영역에 아이콘으로 나타납니다.
아이콘의 도구 설명은 앱의 알림 내용입니다.

- 아이콘을 누르면 앱이 열립니다.
- 마우스 오른쪽 단추로 누르면 **열기**, 알림에 있는 동작, **중지**가 나옵니다.
- **중지**는 먼저 확인을 묻습니다. **다시 묻지 않음**을 선택하면 다음부터 묻지 않습니다. 다시
  묻게 하려면 DSA 설정 **백그라운드에서 실행 중** 페이지에서 **알림 영역에서 앱을 중지하기 전에
  묻기**를 켭니다.
- 미디어를 재생하는 앱은 미디어 키와 Windows 미디어 컨트롤로도 조작할 수 있습니다.

DSA 설정의 **백그라운드에서 실행 중** 페이지에 이런 앱이 나열되며, 앱마다 **열기**와 **중지**가
있습니다. 명령줄에서는 `dsa background`, `dsa background open <package>`,
`dsa background stop <package>`를 씁니다.

## 바탕 화면 위젯

Android 위젯을 바탕 화면에 독립된 창으로 놓을 수 있습니다. 위젯은 다른 창 아래에 있고, 바탕
화면 보기를 해도 사라지지 않으며, 작업 표시줄과 Alt+Tab에는 나타나지 않습니다.

1. DSA 설정의 **위젯** 페이지를 엽니다.
2. **앱이 제공하는 위젯**에서 원하는 위젯 옆의 **바탕 화면에 추가**를 누릅니다. 앱이 위젯 설정을
   요구하면 설정 창이 열립니다.
3. 위젯을 옮기려면 위젯의 아무 곳이나 누른 채 0.5초 동안 움직이지 않습니다. 위젯이 들리며
   테두리와, 크기를 바꿀 수 있는 가장자리마다 손잡이가 나타납니다. 그대로 끌면 옮겨지고,
   손잡이를 끌면 크기가 바뀝니다. 바로 끌면 위젯 자체의 동작이 되므로 위젯의 목록은 그대로
   스크롤됩니다. 들지 않고 위젯의 가장자리를 끌어도 크기가 바뀝니다. 크기를 바꿀 수 있는
   가장자리만 그렇습니다. 놓은 위치와 크기는 DSA가 기억합니다.
4. 위젯을 마우스 오른쪽 단추로 누르거나 길게 누른 뒤 놓으면 **위젯 설정**(위젯을 다시 설정할 수
   있는 경우), **크기 조정**(위젯이 허용하는 크기 중에서 고르기), **제거**가 나옵니다. 메뉴 키나
   Shift+F10으로도 열립니다. 이 메뉴에서는 화살표 키, Enter, Esc를 쓸 수 있고, 글자 키로 항목을
   고를 수 있습니다. **크기 조정**은 R, **제거**는 M입니다.

명령줄에서는 `dsa widgets list`, `dsa widgets add <provider>`, `dsa widgets remove <id>`를
씁니다.

## 링크와 클립보드

- Android 앱에서 누른 웹 링크는 기본 브라우저에서 열립니다. 설치된 앱이 자기 것으로 확인한
  링크는 그 앱에서 열립니다.
- 모든 웹 링크를 Android 앱에서 열려면 DSA 설정 **고급** 페이지에서 **Android 앱에서 웹 링크
  열기**를 켭니다(`dsa settings set links-in-android on`).
- 복사한 텍스트는 Windows와 Android 사이에서 양쪽으로 공유됩니다. 끄려면 **고급** 페이지에서
  **Android와 클립보드 공유**를 끕니다(`dsa settings set clipboard off`).

## Google Play와 보호된 동영상

DSA에는 Google 소프트웨어가 들어 있지 않습니다. 원하면 DSA가 출처와 약관을 보여 준 뒤 출처에서
대신 내려받습니다. 둘 다 다음에 Android를 시작할 때부터 적용되고, 다시 제거할 수 있습니다.

- **Google Play.** DSA 설정 **고급** 페이지의 **Google Play** 아래에서 **설치**를 누르거나
  `dsa gapps install`을 실행합니다. DSA가 내 Android 버전에 맞는 공개 LiteGapps Core
  패키지(Google Play 서비스, Play 스토어, 계정 동기화)를 내려받습니다. 이 Android는 Google 인증
  기기가 아니므로, 기기를 등록하기 전에는 Google이 로그인을 거부할 수 있습니다. **이 기기를
  Google에 등록**에 Android ID가 나오고, 등록 페이지를 열 수 있습니다. `dsa gapps status`는
  상태를 보여 주고, `dsa gapps remove`는 Android가 멈춘 동안에도 Google 앱을 제거합니다.
- **Widevine.** 스트리밍 앱이 보호된 동영상을 재생하려면 Google의 Widevine 모듈이 필요합니다.
  **고급** 페이지의 **보호된 콘텐츠** 아래에서 **받기**를 누르거나 `dsa drm widevine install`을
  실행합니다. DSA가 내 Android 버전용 Google Android 에뮬레이터 이미지(약 2GB)를 내려받아
  Widevine 모듈만 바꾸지 않고 남기고, 나머지는 지웁니다. 여기의 Widevine은 보안 수준 L3이라
  스트리밍 서비스는 표준 화질까지만 보냅니다. 고화질로 보려면 Windows 브라우저나 앱을 쓰십시오.
  `dsa drm widevine remove`로 제거합니다.

## ARM 전용 앱

x64 PC에서 ARM 프로세서용 코드만 있는 앱은 ARM 번역기를 거쳐 실행됩니다. x64 PC의 Android에는
오픈 소스 번역기 Digitalis가 함께 들어 있고, 처음 시작할 때부터 이것을 씁니다. 다른 번역기를
대신 쓸 수도 있습니다.

- **Google의 ARM 번역기.** **고급** 페이지의 **Google의 ARM 번역기** 옆 **받기**를 선택하거나
  `dsa arm-translation fetch google`을 실행합니다. DSA가 먼저 출처와 Google의 약관
  ([Android SDK 라이선스](https://developer.android.com/studio/terms))을 보여 주며, 동의하기
  전에는 아무것도 받지 않습니다. 그다음 PC가 Google이 이 Android 버전용으로 제공하는 Android
  에뮬레이터 이미지(약 2GB)를 받아 번역기만 남기고 나머지는 지웁니다. DSA는 Google의 번역기를
  싣거나 다시 배포하지 않습니다.
- **직접 만들거나 따로 구한 패키지.** 오픈 소스 번역기 Digitalis로 만든 패키지 같은 것입니다:
  `dsa arm-translation install <folder>`

그다음 Android를 다시 시작합니다. DSA 설정 **일반** 페이지에서 Android를 종료한 다음 앱을 엽니다.

Android에 함께 들어 있는 번역기로 돌아가려면 **고급** 페이지의 **기본 번역기 사용** 옆 **사용**을
선택하거나 `dsa arm-translation use-default`를 실행합니다. 설치한 패키지를 지우며, 다음에
Android를 시작할 때부터 적용됩니다.

Android가 쓰는 번역기는 `dsa arm-translation status`로 확인합니다. **고급** 페이지의 **ARM 전용
앱 실행** 스위치는 아무것도 지우지 않고 번역을 켜거나 끕니다. ARM 코드와 x64 코드가 모두 있는
앱은 **앱** 페이지의 **ARM으로 실행**(`dsa apps run-as-arm <package> on`)을 켜면 ARM 코드로
실행됩니다. 64비트 ARM 앱(`arm64-v8a`)만 실행할 수 있습니다. ARM64 PC에서는 Android가 ARM 앱을
직접 실행하므로 번역기가 필요 없습니다.

## 루트 권한

백업 도구처럼 루트가 필요한 앱이 있습니다. DSA는 Linux PC의 `sudo`와 같은 방식으로 루트를
줍니다. PC의 관리자가 승인할 때만, 요청 하나씩 줍니다. 기본값은 꺼짐이고, 허용되지 않은 앱에는
`su`가 아예 보이지 않습니다.

1. 관리자가 DSA 설정 **고급** 페이지의 **루트 권한** 아래에서 **Android 앱의 루트 권한 요청
   허용**을 켭니다(`dsa settings set root-elevation on`). 다음에 Android를 시작할 때부터
   적용됩니다.
2. **앱** 페이지에서 앱의 **루트 권한**을 정합니다.
   - **루트: 요청 불가**(기본값): 앱에 `su`가 없습니다.
   - **루트: 요청할 때 묻기**: 앱이 `su`를 쓸 때마다 Windows가 앱 자신의 이름과 아이콘으로
     관리자 확인 창(UAC)을 띄웁니다. 표준 사용자는 관리자의 암호를 입력합니다. 승인은 그 앱에
     대해 15분 동안 유지됩니다.
   - **루트: 기억(묻지 않음)**: 앱이 묻지 않고 `su`를 씁니다. 이 수준을 고르려면 관리자 승인이
     필요합니다.

   명령줄에서는 `dsa apps root <package> off|ask|remember`를 씁니다.

개발자 모드가 켜져 있으면 `adb shell`도 `su`를 쓸 수 있습니다. **앱** 페이지에 **adb 셸**이라는
자기 행이 있고, 기본으로 매번 묻습니다(`dsa apps root adb ask`). 이 확인 창의 이름은 **adb
셸**이고, 실행할 명령을 보여 줍니다.

Android 자체의 구성 요소가 요청하면 확인 창에 그 이름이 나옵니다: **Android 시스템**, **Android
전화 서비스**, **Android 블루투스**, **Android NFC**, **Android 시스템 서비스**. 사용자 ID 하나를
함께 쓰는 앱들은 한 묶음으로 승인되며, 확인 창에 모두 나옵니다.

모든 요청은 앱, 시각, 명령, 승인 여부와 함께 서비스 로그에 남습니다. 기능을 끄면 다시 시작하지
않아도 모든 앱에서 `su`가 바로 사라집니다.
