Findings that change the test plan:
1. The previous session's test A was invalid. runA.sh used "swapoff -a", which this toybox
   rejects ("swapoff: Needs 1 argument"); swap stayed on. It also started at uptime 790 s, not
   at boot. "swapoff /dev/block/zram0" works (done at 994 s in that boot, SwapTotal 0 after).
2. The panic is not deterministic: two boots ran 15 minutes with swap on and many reclaims
   and trims, two died at 103 s and 291 s. One clean 15 minute run of A or B proves nothing;
   each condition needs several boots.
3. A property loop cannot block the reclaim after boot: init queues the trigger's actions
   when the property becomes 1, so setting it back to 0 is too late. Root (u:r:dsa_su_root)
   shares init's mount namespace and "mount --bind <file> <target>" works there, so
   scripts/runB.sh binds a plain file over /sys/fs/cgroup/memory.reclaim. That blocks the
   trim's write too (same kernel path, user_proactive_reclaim); drop_caches and the zram
   idle/recompress/compact writes still run. setprop vendor.dsa.memory.reclaim works as root.
4. The installed image's trim writes "swappiness=30" (console: dsa-channeld.rc:112), while
   develop's dsa-channeld.rc says "swappiness=0". The image under test is older than the source.
5. C4 died 103 s after boot, before any approval could be given by hand. A test that needs
   a human approval after boot cannot cover the early window. A way to apply the condition
   without the prompt is needed (for example "dsa apps root com.android.shell remember",
   which is the owner's setting to change, or a kernel command line / image change).
